# 讲座可行性探针（Probe）

本目录存放一个**只读的研究工具**，用于回答一个具体问题：

> 讲座是否会作为一门「课」，带着 7 位 `courseSchedId` 出现在个人课表里？

这个问题的答案决定了「讲座签到」能做到什么程度：

- **会** → 讲座可以直接复用现有的一键/自动签到通道；
- **不会，但出现在课程列表里** → 讲座可以展示，签到需要另找节次标识；
- **完全查不到** → 讲座不在该系统内，需要改用外部活动源做展示。

## 探测项一览

| 编号 | 名称 | 输入参数 | 说明 |
| --- | --- | --- | --- |
| A1 | 我的课程 | — | 既有：课程列表通道 |
| A2 | 全部课程 | — | 既有 |
| A3 | 学期列表 | — | 既有 |
| A4 | 日课表 | `--dates` / `--days-ahead` | 既有：单日课表 |
| A5 | 周课表 | — | 既有 |
| **A6** | 历史讲座判定 | `lectures.historicalDate` + `lectures.historyKeywords` | 在日课表（及 A1/A2/A5 通道）里定位已结束的讲座，记 `id`/`uuid`/`courseId`/`courseNum`/`signStatus` |
| **A7** | 未来讲座判定 | `lectures.futureDates` + `lectures.historyKeywords` | 同上，用于现场验证 |
| **B1** | 桥接判定 | `bridge.*` | 课表侧 `courseId`/`courseNum` 与注册表 5 位 `cId` 是否同一编号体系（含 7 位负对照） |
| **B2** | 讲座在册定位 | `--registry-cids` + `lectures.knownCids` + B4 命中集 | 按关键词在注册表确认 `cId`；**只读课程名与编号** |
| **B4** | `cId` 分段扫描 | `--cid-scan` / `--cid-start` / `--cid-end` / `--cid-limit` / `--cid-step` / `--cid-suffix` | 默认扫末两位为 `00` 的 5 位 `cId`（约 900 个）；`--cid-step 1 --cid-suffix ""` 即全量密扫。统计讲座类占比与分段分布，**支持分批续扫** |
| **B6** | 追加前沿哨兵 | `--sentinel` / `--sentinel-span` / `--sentinel-lookback` | 编号**只增不改**，故新条目必然落在「既有最大有名称编号」之后。窗口 = 前沿之后 `span` 个 + 向前回看 `lookback` 个（回看用于补采「先占号、后填名」的条目），下界受 `term.anchorCid` 截断（本学期第一场讲座所在编号），用来接住 `M1168` 这类**尚未开出**的后续场次 |
| **B7** | 讲座编码目录 | `--catalog` | **0 次发包**：把已扫到的课程名归纳成「系列 → 期次 → 编号 → 学期 → 任务号」，写出 `out/lecture_catalog.json`；含 `term` 区段（本学期下界与已见期次） |
| **C1** | 候选接口发现 | `candidates[]` | 只读 GET 探测「按课程反查节次」的可能路径，判定存在/不存在/需鉴权/参数错误 |

判定只看**日期通道**（日课表）；A1/A2/A5 里的命中会作为「非日期通道」佐证列出，但不计入 A6/A7 的阳性/阴性。

## 为什么交付物是一个打包文件

触碰学校后台的代码不应公开。因此：

- **源码不进入仓库**（`.gitignore` 已排除相关路径），只在本机存在；
- **端点配置不进入仓库**：所有主机、端口、路径与动作名集中在本地配置文件中，
  仓库内仅保留一份不含真实值的模板说明；
- 仓库中提交的是打包后的可执行产物 `iclass_probe.pyz`，其**内容不含任何端点字面量**
  （即使被解包，也读不到后台地址）。

> 注意：打包本身不是安全边界，只是提高门槛。真正的防线是「端点不落库」。

## 使用方式

### 1. 准备端点配置

在本目录创建 `endpoints.local.json`，填入真实的端点值。文件结构为：

```json
{
  "host": {
    "api": "<移动端 API 根地址，以斜杠结尾>",
    "registry": "<课程注册表服务根地址，以斜杠结尾>",
    "ua": "<移动端 User-Agent>",
    "uaLogin": "<登录用 User-Agent>",
    "verifyTemplate": "<登录请求体内的校方校验地址模板，保留 ${0} ${1} ${2} 占位符>"
  },
  "ops": {
    "login": "<登录动作>",
    "clock": "<校时动作>",
    "day": "<单日课表动作>",
    "week": "<周课表动作>",
    "terms": "<学期列表动作>",
    "mine": "<我的课程动作>",
    "mineAll": "<全部课程动作>",
    "sign": "<签到动作>"
  },
  "registry": {
    "page": "<注册表页面路径>",
    "param": "<动作参数名>",
    "detail": "<读取课程与名单的动作值>",
    "stats": "<考勤统计动作值>",
    "remove": "<移除名单动作值>",
    "titlePattern": "<用于提取课程名的正则>",
    "codePattern": "<用于提取复合编码的正则>"
  },
  "lectures": {
    "historicalDate": "<历史讲座日期 yyyyMMdd>",
    "futureDates": ["<未来讲座日期 yyyyMMdd>"],
    "historyKeywords": ["<定位讲座用的关键词，含姓名关键词>"],
    "nameKeywords": ["<姓名类关键词：源码不内联，报告里替换为 REDACTED>"],
    "registryKeywords": ["<在注册表里找讲座用的关键词>"],
    "knownCids": [0],
    "b2MaxLookups": 20
  },
  "bridge": {
    "idKeys": ["<课表条目里表示课程层编号的键>"],
    "nameKeys": ["<课表条目里表示课程名的键>"],
    "maxLookups": 8,
    "sampleIds": [0]
  },
  "scan": {
    "start": 10000, "end": 100000, "step": 100, "suffix": "00",
    "matchKeywords": ["讲座", "讲堂", "报告会"]
  },
  "sentinel": {
    "span": 50,
    "lookback": 50,
    "lectureKeywords": ["讲座", "讲堂", "报告会", "明德", "论坛"]
  },
  "catalog": {
    "seriesLabel": "<期次号系列的名字，如「明德讲堂」>",
    "sessionPrefix": "<期次号前缀，如 M>",
    "sessionPattern": "<从课程名里抽期次号的正则，需含一个捕获组>",
    "seriesKeywords": ["讲座", "讲堂", "论坛", "报告会"],
    "denseFrom": 57000,
    "minSeriesCount": 2,
    "maxSeriesRows": 40,
    "maxSessionRows": 20,
    "indexFile": "<cId → 复合码的本地索引文件名>",
    "outFile": "lecture_catalog.json"
  },
  "candidates": [
    { "key": "<代号>", "op": "<候选 GET 路径>", "desc": "<用途>",
      "params": { "<参数名>": "${user_id}" } }
  ],
  "limits": { "maxRequests": 60, "minIntervalSec": 0.8 },
  "blockedOps": ["<签到动作全路径>", "<移除名单动作全路径>"]

```

`blockedOps` 是**写操作禁列表**，工具会硬编码校验并拒绝发出这些请求，
无论配置如何改动都不会触碰到它们。C1 的候选路径也只能写在配置里，源码不留任何路径字面量；
参数值里的 `${user_id}` / `${courseId}` / `${cId}` / `${dateStr}` 由探针在运行时填充。

### 2. 先干跑，确认请求清单

```bash
python iclass_probe.pyz --config endpoints.local.json --dry-run
```

干跑只打印计划发出的请求，不产生任何网络流量。无参数启动（`python iclass_probe.pyz`）
只打印用法，不会去连任何东西。

### 3. 正式运行

```bash
python iclass_probe.pyz --config endpoints.local.json \
  --dates 20260916 \
  --registry-cids 60702
```

- `--dates`：你**曾实际参加过讲座**的日期，用于验证讲座是否出现在当日课表；
  不填则探测今天起的一段时间。
- `--registry-cids`：可选，按课程编号做定向查询，用于确认某场讲座是否登记在册。
- 运行时会**交互式**要求输入账号与密码，密码不回显。

### 4. B4 批量扫描（务必分批）

约 900 个候选编号不可能一轮跑完（默认上限 60 次请求）。扫描是**增量**的：
累计结果写在 `out/b4_scan_state.json`，重复运行同一命令会**只扫没扫过的**，
并把累计结果合并进报告。

```bash
# 第一批：最多新扫 30 个（其余额度留给 A/B/C 探测）
python iclass_probe.pyz --config endpoints.local.json --cid-scan --cid-limit 30

# 第二批：继续扫下一段（已完成的部分自动跳过）
python iclass_probe.pyz --config endpoints.local.json --cid-scan --cid-limit 30 \
  --cid-start 10000 --cid-end 40000
```

- `--cid-start` / `--cid-end`：扫描区间（不含 `end`），默认取配置 `scan.start` / `scan.end`。
- `--cid-limit`：本批最多新扫多少个；`0` 表示「用尽本轮剩余额度」，仍受 `limits.maxRequests` 约束。
- 频率沿用 `limits.minIntervalSec`（默认 0.8 秒/次），**不会加速**；单条失败只记录，不中断整体。

产出：`out/report.md`、`out/raw/*.json`、`out/b4_scan_state.json`。

## 本轮实测结论（2026-09-16）

### 1. 性能前提：必须复用连接

「每个请求新建连接」的写法在本机实测**恒定 ~12.6 秒/请求**（与响应大小无关：`500` 错误、
1.6 KB 页面、18 KB 页面一样慢），照这个速率扫 900 个候选要 3 小时以上。
改用**同一 keep-alive 连接**后实测 **0.11–0.45 秒/请求**：900 个约 6 分钟、5500 点密扫约 37 分钟。
本工具用 `requests.Session`，**已经复用连接 —— 做批量扫描时不要改成每次新建连接**。

### 2. 不需要凭据也能跑：`--registry-only`

课程注册表目录是**匿名只读**的，因此编号枚举完全不需要账号。
`--registry-only` 跳过登录，只跑 B4 / B2 / B1（编号层对照），
也就是说「找讲座编号」这件事**不必交出账号密码**。桥接判定（决定能否签到）仍需登录态。

### 3. 密扫：`--cid-step` / `--cid-suffix`

```bash
# 全量密扫某个学期区段（步长 1、不限后缀）
python iclass_probe.pyz --config endpoints.local.json --registry-only --cid-scan \
  --cid-start 58900 --cid-end 64400 --cid-step 1 --cid-suffix "" --out out/dense.md
```

- 长扫描要先把本地配置 `limits.maxRequests` 调到足够大（例如 6000），
  并**保持 `minIntervalSec` 不被调小**；也可以用 `--cid-start` / `--cid-end` 分段。
- 累计进度仍写 `out/b4_scan_state.json`，中断后重跑同一命令会续扫。

### 4. 找「下一场」：B6 哨兵 + B7 目录

全库密扫一次是数千请求，不适合频繁跑。**B6 只扫追加前沿附近的窄窗**：

```bash
# 默认窗口 = 前沿之后 25 个 + 向前回看 25 个 = 50 个请求，约 20 秒
python iclass_probe.pyz --config endpoints.local.json --sentinel --out out/report_sentinel.md
```

- 窗口 = `sentinel.span`（向前）+ `sentinel.lookback`（回看），**两者之和应 ≤ `limits.maxRequests`**；
  想一轮覆盖更多天，把 `limits.maxRequests` 一起调大再跑。
- B6 会顺带跑 B7，把 `out/lecture_catalog.json` 刷新一遍（**0 次发包**）。
- **回看不能去掉**：条目会「**先占号、后填名**」（实测锚点页初建时 1.6 KB 无标题，后补全为 8.6 KB），
  只向前扫会永久漏掉这些条目。回看使每个编号至少被复查两轮。
- **回看大小要跟着前沿漂移走**：`lookback` 必须 ≥ 两次运行之间前沿推进的编号数。
  开学选课期课程注册会把前沿一天推高几百个，此时沿用 25 的回看、隔几天才跑一次，
  期间的讲座会被**整段越过**。B6 每轮都会报出 `前沿漂移=`（较上轮 +N），
  漂移超过回看窗口时直接告警，据此决定加大回看还是缩短间隔。
- `--sentinel-span` / `--sentinel-lookback` 可临时覆盖两个窗口；只做目录归纳用 `--catalog`。

产物：`out/lecture_catalog.json`（系列/期次/编号/学期/任务号，含 `term` 区段）、`out/report_sentinel.md`。

> **不要**把起点设成「上一次讲座的编号」：**编号顺序 = 注册先后，不是讲座日期先后**。
> 本学期实测有 100+ 个「同名连号块」（如 `全球地缘与中国国情专题讲座` 在 `60056`–`60066` 连号 11 条），
> 属整学期**成块预注册** —— 12 月才开讲的场次，其编号可能远小于 9 月那场明德讲堂。
> 以「上次讲座编号」为起点会漏掉它们；以**全库前沿**为起点才安全，且能**提前**发现未开讲的场次。

### 4.1 扫描区域：按学期下界截断（`term.anchorCid`）

**`M1167`（2026-09-16）是 2026 秋学期第一场明德讲堂**，其编号 `cId 64241` 就是本学期讲座**事件**区的下界。
学期边界取自复合码前 10 位（权威口径，非按编号估计）：

| 区段 | 学期号 | `cId` 区间 | 内容 |
| --- | --- | --- | --- |
| 春季学期 | `2025202602` | `≤ 58424` | 上学期，末场 `M1166` 在 `58402`–`58404`；**已封口** |
| 暑期 | `2025202603` | `58425 – 58927` | 66 条 |
| 本学期注册区 | `2026202701` | `58928 – 64298` | 5367 条：开学批量导入的课程，**含 13 个「专题讲座」类课程容器（71 条）** |
| **本学期讲座事件区** | 同上 | **`64241 –`** | 逐场追加的讲座场次，首场即 `M1167` |

「事件区」与「注册区」是两件不同的事，别混：
**学期初批量导入**的是讲座**课程容器**（如 `全球地缘与中国国情专题讲座` 在 `60056`–`60066` 连号 11 条、
`发现生命奥秘专题讲座` 16 条），它们散落在 `58928`–`64240`；
而**逐场追加**的讲座场次（明德讲堂每场 3 个连号）从 `64241` 起。

这三段是实测划出来的，不是估计：密扫结果里 `M1166`（`58417` 末位）与 `64241` 之间
**一个 `M` 期次都没有**，且 `M1167` 就是全库最高期次号 —— 故它确实是本学期第一场。

由此，扫描策略变成：

- **区域**：B6 的窗口下界被 `term.anchorCid` 截断，**永不回看 `64241` 以下**——
  上学期、暑期与开学导入区都已确认不含讲座**事件**，重复扫描纯属浪费。
- **顺序**：自前沿向上（编号只增不改），新场次必然出现在前沿之上。
- **前沿只认密扫证据**：`x00` 抽样网格同样是「有名称」的，若把抽样点算作前沿，
  前沿会被抬到一个本学期还没分配到的位置，哨兵随之跳到那里，
  **整段真正的新讲座区被跳过**。因此前沿只在「相邻编号也被扫过」的编号里取最大值
  （密扫区连成一段，抽样点是孤立点）。已用构造数据验证：混入孤立的 `70000` 抽样命中时，
  旧口径会把前沿误判为 `70000` 并去扫 `69975~70025`，新口径仍正确取 `64298`。
- **命中按「场」归并**：一场讲座占 3 个连号（三校区各一条），
  B6 报的是「新增 N 场」而不是「新增 N 个编号」，避免误以为一场要签三次。

### 5. Wave 1 结论：明德讲堂**在册**（旧结论被推翻）

| 项 | 结果 |
| --- | --- |
| 明德讲堂期次号 | **52 个**（`M875`–`M1167`），共 159 条 `cId` |
| 锚点 `M1167` | `cId 64241`（中关村）/ **`64242`（雁栖湖）** / `64243`（玉泉路） |
| 结构性规律 | **一场 = 3 个连续 `cId`**（三校区各一条），跨 47 期验证 |
| 任务号（复合码中段） | 明德常用 `242624`，但**非唯一**：`M1167` 雁栖湖场是 `88414` → 不能当系列主键 |
| 注册表可签到标识 | **7 位 0 个 / 32 位 hex 0 个** → 注册表侧没有 bridge |
| 注册表字段面 | 只有编号 / 任务号 / 学期 / 课程名；**无日期、无场地** |
| 旧假设「讲座集中在 `x00`」 | **不成立**：900 个 `x00` 仅命中 22 条；锚点落在采样网格之外 |

完整证据见 `out/report.md`（脱敏）；对开发的约束见 `docs/lecture-signin-research.md` §10。

### 5. 其它讲座类型的形态与节奏（B7 + feed ↔ 注册表 join）

`out/lecture_catalog.json` 的结论，按「像不像可复现的标识」排序：

| 观察 | 结论 |
| --- | --- |
| 复合码中间段（页面称**任务号**） | **不是系列标识**：同名系列跨多个任务号，且一个任务号下混装不同系列 → 不能拿它当系列主键。`194435` 出现 **815** 次（通用占位批次），`242624` 220 次（明德专用） |
| 真正稳定的标识 | **课程名本身**。同一系列的多场用同一课程名重复注册（如「全球地缘与中国国情专题讲座」11 条同名） |
| 批次注册 | 同一系列的整学期场次常**成块连号**注册（本学期 ≥ 5 连号同名块 100+ 个）→ 后续场次可能**提前**就已在册 |
| 明德讲堂特殊 | 名称内嵌期次号 `M<NNN>`，且**一场 = 3 连号 `cId`**（三校区） |

把公开 feed 的 `title` 与注册表课程名 join（人文 **114/114**、科学 **341/345** 命中，
两份数据**同源**），可以量化形态与节奏。**注意必须按「不同 `cId` 个数」统计**：

| 一场占几个不同 `cId` | 人文（36 场） | 科学（267 场） |
| --- | --- | --- |
| **3 条**（三校区平行） | **32** | 0 |
| 2 条 | 1 | 0 |
| **1 条**（单点） | 3 | **267（全部）** |

> `一场 = 3 连号` 是**「三校区平行讲座」这一形态**的特征（明德讲堂 32/36 场属此类），
> **不是所有讲座的通则** —— 科学类讲座一律一场一条。

| 注册节奏 | 判定 | 人文 | 科学 |
| --- | --- | --- | --- |
| **逐场追加** | `cId` 顺序 == 日期顺序 | **5/5 系列** | 14 个系列 |
| **成块预注册** | 两者不一致 | 0 | **9 个系列** |

极端例子：`电磁脉冲探测前沿讲座` 8 场横跨 7 周（04-01–05-20），`cId` 却只跨 `57159`–`57184`（**宽 26**）
→ 学期初**一次性注册完整学期**。这就是第 4 节「不能以『上次讲座编号』为扫描起点」的成因。

**开课节奏**：明德约 2–3 场/周（单主题 0.3–1.8 场/周）；
科学类分化极大 —— 高端论坛 4.6–4.9 场/周、集中授课 7.0 场/周（每天连排）、常规系列约 1 场/周。

**时段**：明德集中在**晚上**（18:00 / 19:00 共 83 场）；科学类集中在**下午**（13:00 约 106 场）。

**注册表字段面**：只有 `cId` / 任务号 / 学期 / 课程名；**没有日期、没有场地**
→ 注册表单独**排不出讲座日历**（日期命中 0、场地命中 0）。

**公开 feed 的滞后**：两份快照 `generatedAt` 均为 **2026-04-30**，最新只覆盖到 5 月下旬；
而**课程注册表实时**，本学期已有 **70** 条讲座类条目、含 9-16 的 `M1167`。

> **注册表领先公开 feed 约 4.5 个月。** 哨兵能在 feed 更新前数月就报出「**已排期、名称为 X**」的新讲座
> —— 代价是**拿不到日期**（注册表不含日期）。这是「比 App 现在的旧快照更新」与「没有时间」之间的取舍。

## 隐私与安全约束

1. **凭据**：仅交互式输入，不写盘、不读环境变量、不进入命令历史。
2. **脱敏**：登录令牌、用户 id、学号在落盘前统一替换为 `<REDACTED>`，
   课表内的 7 位节次标识会被保留（这是分析对象，不是身份信息）。
   `lectures.nameKeywords` 里的姓名类关键词在源码与报告里都不出现（报告里替换为 `<REDACTED>`）。
3. **不采集他人信息**：工具不解析、不打印、不落盘任何他人姓名或学号；
   考勤统计查询只允许使用本人学号。注册表接口的响应正文（含成员名单）一律不保留，
   只留状态码与长度；B2/B4 只取课程名与编号。
4. **频率与总量**：默认最多 60 次请求、间隔不小于 0.8 秒；B4 必须分批续跑。
5. **只读**：工具不执行任何写操作，`stu_scan_sign` 之类的签到动作既不在候选列表里，
   也被 `blockedOps` 硬拦截。
