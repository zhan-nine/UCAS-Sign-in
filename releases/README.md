# 发布安装包

本目录存放面向用户的 Release APK，文件名形如：

```text
qingxin-signin-<version>-release.apk
```

当前推荐版本：`qingxin-signin-1.2.0-release.apk`

> **本目录只保留最新一个安装包。** 历史版本已移出版本控制
> （`.gitignore` 只放行当前版本，其余 `releases/*.apk` 一律忽略），
> 需要旧版请从 git 历史中检回。

## 版本要点

### 1.2.0（当前）

自 1.1.13 起的全部改动都收在这一版，因此下面按**能力**而不是按版本号来写。

#### 新增：讲座页（首页右上角「讲座」进入）

**数据来源：两个，各有各的边界。**

| 来源 | 给什么 | 前提 |
| --- | --- | --- |
| 讲座预约系统 | **讲座日期 + 起止时间 + 场地** | 需登录（验证码 / 邮箱验证） |
| 人文学院网站通知 | 标题、期次号、发布日 | 免登录、可后台检查 |

学院网站的通知**没有讲座时间与场地**（实测预告正文多为海报图片，日期印在图上），
而预约系统的表是唯一同时给出时间与场地的来源。它必须登录，因此做法与桌面端
[UCAS-Desktop](https://github.com/zhangzhendan-Berkeley/UCAS-Desktop) 一致 ——
**把真实登录页放进应用内嵌页面，由你亲自登录**：

- 应用**不保存账号密码**，不模拟提交登录表单；会话由 WebView 的 Cookie 存储自己管，
  本应用不接触、不导出、不落盘任何 Cookie；
- 打开讲座页后先完成 SEP 登录，再点「人文讲座 / 科学前沿」；
  应用会自动走桌面端那条链路：**SEP 工作台 → 选课系统 → 讲座预告 → 列表页**
  （直开栏目 URL 只会拿到 401，见下方「修复」）；
- 停在列表页且表头出现后**自动读取**，也可手动「重新读取」；
- 读取只发生在你眼前那一页，不做任何后台上传；两栏独立，读一栏不会清掉另一栏。

**为什么不能像通知那样后台自动更新**：它需要登录，而登录需要人。这是数据源的固有属性，
不是实现上的取舍 —— 所以界面上会**显式标出上次读取时间**，由你自己判断这份数据有多新。

**列表分三段，判据按来源分开、不能混用：**

| 段 | 收什么 |
| --- | --- |
| 即将开始 | 预约系统读到的、尚未结束的（有确切日期），按时间升序 |
| 暂无举办日期 | 学院网站通知，尚无报道、也还没读到时间 |
| 往期 | 已结束（有时间按结束时刻；无时间按报道），默认折叠 |

| 条目来源 | 是否已结束的判据 | 证据强度 |
| --- | --- | --- |
| 预约系统（有时间） | `讲座日期 + 结束时刻` 早于当前时刻 | **硬证据** |
| 学院网站（只有标题） | 同一期次号下出现过「报道」 | 间接，会滞后 |
| 学院网站（只有标题，且发布已超 14 天、仍无报道） | 无报道可等，按发布时长保守归入往期 | 弱信号，仅兜底 |

拿时间比一条**没有时间**的通知，等于按发布日期猜讲座日期 —— 因此三者不能合并成一条规则。
「暂无举办日期」独立成段是有意的：发布日 ≠ 讲座日，把这类条目放进「即将开始」
等于谎称知道日期。

**同一场讲座不再重复出现。** 一场讲座在两个来源里各有一条，此前会各展示一行，
而且两行各只有一半信息（一行有时间没详情、一行有详情没时间）。现在按
**期次号**（`M1167` / `213`）合并成一条：时间场地取预约系统、详情链接取学院网站。
合并只认期次号，标题太短时不做包含匹配 —— 「讲座」这种两字标题会命中一大片，
把详情链接挂到别的讲座上比不合并更糟。

**「已结束」用站内证据判定，不按日期猜。** 同一个期次号下已经出现「报道」的场次标为已结束。
报道常在讲座后数日到数周才发，因此「没有这个标记」**不等于**讲座还没开始 ——
宁可少标，也不猜：猜错的代价是用户以为讲座还没开始而白跑一趟。

**其它**

- 栏目筛选「全部 / 明德讲堂 / 艺术与人文修养」三者**互斥**（选中项是单个可空值，
  非法状态在类型层面就不存在）。
- 讲座通知**每次从网页直接拉取**，不读本地缓存：缓存恰恰是滞后性的来源，
  对「最新通知」来说「看起来有数据但其实是旧的」比「明确告诉你没网」危害更大。

**标注为「测试中」。** 这一组功能的判据仍在演进（数据源分两类、已结束的判据按来源分开、
外加一条 14 天的兜底启发式），因此在讲座页标题、讲座预告页标题、以及哨兵 / 新讲座通知
两张卡片上统一挂了「测试中」徽章，并在来源说明里写明「以预约系统与学院网站的原始页面为准」。

#### 新增：手动打卡独立成页

- 与讲座**没有耦合**：签到通道就是普通课程那条（`stu_scan_sign.action`），
  只认 7 位 `courseSchedId` 或 32 位 `timeTableId`。现场读到编号即可打卡。
- 新页面**不加载任何列表数据**，进页即可用（断网也能正常报错）；自动聚焦并弹出键盘；
  **边输边判定**格式，不合格的输入**不发任何请求**。
- 编号识别抽成纯函数（`SignCode`）并单独单测：位数不对、全角数字、`123-4567` 这类
  「用连字符凑数」的输入一律拦下 —— 放宽的代价是输入框变成「可以向任意编号发签到请求」的通道。
- 讲座页保留入口：看完讲座预告后接着想去打卡是自然的连续动作。

#### 新增：自动打卡排除名单

- 「今日跳过」只对今天生效；「长期不打卡」一直生效，两者都可随时取消。
- 修改后立刻重排闹钟 —— 被排除的课可能正是刚排好的下一次唤醒，
  不重排就会在那节课上白醒一次（并且真的签上去）。

#### 新增：按日期看课表

- 首页右上角「课表」进入，可查看**任意一天**的课程。
- 输入支持 `2026-09-20`、`20260920`、`2026年9月20日`、`9-20` 等形态，
  中文输入法的**全角**数字与连字符会被归一化；无法识别时明确提示，**不替你猜**。
- 越界日期一律拒绝：`2026-02-30` 会报错，而不是被悄悄顺延到 3 月 2 日。
- 缓存优先：翻回看过的日期先用缓存立刻渲染，再等网络结果覆盖，不会白屏。
- **这一页只看不签**，也不写入首页那条「今天」的数据流，因此守护进程不会把明天的课
  当成今天的课去签到。

#### 新增：提前发现下一场讲座（哨兵，默认关闭）

- 课程注册表里讲座按排期**逐场追加**、编号只增不改，因此从本机记录的最后一个编号向前扫即可。
- 同时**复查「占号但还没填名」的编号** —— 实测条目会先占号后填名，只往前扫会漏掉整场讲座。
- 遇到连续 30 个无名称即认定到达分配末端；每轮只发几十次只读请求，只读课程名，无任何写操作。
- 注册表**不含日期与场地**，因此它只能回答「有新讲座、叫什么」，不能替代预约系统。

#### 新增：新讲座通知提醒

- 周期性后台检查学院网站，出现**新的可参加**通知时提醒一次，带开关。
- 与哨兵共用同一个 12 小时周期任务；两者开关独立，因为信息来源与可信度不同。

#### 新增：版本更新提示

- **进主页自动检查**本仓库的 GitHub Releases（12 小时内最多一次）；发现版本号更高的 Release 时，
  主页顶部出现横幅，可点「去 GitHub 更新」在**浏览器**打开该 Release 页
  （应用不做应用内下载，也不做安装器 —— 由你在浏览器里看清要装的是什么）。
- **三种「不打扰」语义刻意分开**：
  「稍后」= 本次会话不显示，下次启动仍提示；「不再提示」= 忽略**这一个版本**
  （将来出现更高的版本仍会提示）；设置页的「自动检查更新」= 总开关。
- 设置页新增「关于 / 更新」卡片：当前版本号、自动检查开关、手动「检查更新」、
  已忽略版本与「恢复提示」。
- **按版本号比较，不按发布时间**：列表按发布时间倒序，历史上发布顺序与版本号顺序并不一致
  （`v1.1.8` / `v1.1.10` / `qingxin` 三者交错），因此读列表并取**版本号最大**的一条，
  而不是用 `/releases/latest`。草稿与显式勾选预发布的条目跳过。
- tag 形态很杂（`v1.1.8`、`qingxin`、`android`），因此版本号解析兼容 `v` 前缀、
  少于三段、以及 `alpha` 这类后缀；解析不出时回退去读 Release 标题里的版本号。
- **失败时静默**：网络不通或 GitHub 限流只在设置页给一句「检查失败，请稍后重试」，
  主页横幅不会有任何变化 —— 一次断网不该让主页多出一句用户此刻也无能为力的报错。
- 隐私：这里只对 GitHub 的公开接口发一次只读 GET，**不带账号、token 或设备标识**。
  GitHub 的地址是公开且通用的（与本项目公开仓库一致），不属于「校内端点」，
  因此它直接写在源码里，而不像 iClass / 讲座源那样走 `local.properties`。

#### 修复

- **讲座页拿不到列表，只见一行 `{"code":401,"msg":"未登录或会话已过期"}`。**
  根因是「登录了 SEP 就直接打开讲座栏目 URL」——未建会话时栏目会 302 到 `/redirect`，
  再被脚本扔到 `/appStore`，而后者在被当成 API 请求时直接返回 401 JSON。
  现在按桌面端做法把会话链路补全：**SEP 工作台 → 选课系统门户（带票据、不硬编码）→
  选课主页菜单里的「讲座预告」桥接 → 栏目页**，并确认表头含「讲座时间 / 讲座名称」后才解析；
  落到 `/redirect` 或正文是 401 JSON 时自动拉回 SEP 登录页。
- **无日期的学院网站通知被算进「即将开始」**，看起来像日期判定坏了。现已拆出独立的一段。
- **选择讲座类型筛选时闪退。** 上游公开源会逐字重复同一场讲座，而条目标识是从
  「会场编号 + 日期 + 时刻」派生的，重复行必然派生出同一个标识；该标识被用作列表项 key，
  一渲染重复 key 就抛异常。现在数据进入界面前先剔除重复行（解析层与缓存读取层各兜一次），
  并让派生标识把日期与起止时刻一并纳入。
- **讲座抓取会抓成一门普通课程。** 旧实现只用「关键词子串」从课表里筛讲座，
  而 `系列` / `前沿` / `人文` / `论坛` 都是普通课程名的常见词。现在判定词与分类词分离：
  只有含「讲座 / 讲堂 / 报告会 / 学术报告」的课程名才会被判为讲座。
- **只有 32 位 `timeTableId` 的课程无法签到**（此前只带 `courseSchedId` 参数，
  发出去必然失败）。现在按标识形态自动选择参数，一键签到与二维码构造共用同一套判定。
- **自动打卡排除名单静默失效。** 本地课表缓存漏存了 `courseId` / `courseNum` 两个课程层标识，
  而排除名单正以它们为键；走缓存路径时键退化成「节次号」或「课程名+教师」，
  于是那门课照签不误，而开关明明是打开的。现已补齐字段（旧缓存缺字段时退化为原行为，
  下次联网自动补齐），并补了一组单测钉住这两个字段。
- **周课表回退时会把整周课程写进单日缓存。** 所查日期没有课时学校接口会回退返回整周数据，
  缓存键的字面含义是「那一天的课」。现在落盘前先裁回所请求的那一天。
- **哨兵一直报「课程注册表连接失败」。** 根因是注册表为**明文 `http`**（实测该端口不支持 https，
  TLS 握手直接报 `WRONG_VERSION_NUMBER`），而应用全局禁止明文流量，请求根本没发出去；
  该异常在界面上与「网络不通」无法区分。现在网络安全配置改为**构建时生成**，
  只放行注册表**那一个域名**，其余仍是「仅系统 CA + 禁明文」——
  不图省事写 `usesCleartextTraffic="true"`，那是对**全部域名**放开明文，包括签到接口所在主机。
- **脱敏漏掉「裸主机名」。** 连接失败那条异常**自带主机名**，而这类文案会落盘、显示在界面上、
  并进入用户复制出去的 bug 报告；原先的脱敏只认 `scheme://authority` 形态。
  现在按**形态**匹配（URL 整条 + 裸主机名 / 内网 IP 含端口），并补了离线单测。
  已知取舍：`docs/README.md` 这类文件名会被一并抹掉 —— 宁可误伤文件名，也不放过一个可能的校内主机名。
- **解析层去重键过窄，会丢掉「报道」。** 同一场次正文相同的预告与报道曾被当成重复行丢掉一条
  （此前没出问题纯属顺序侥幸：RSS 最新在前，报道先出现因而先被保留）。
  现在解析层只挡「整条全同」的重复，预告/报道的合并在「按场次归并」那一层做；
  回归用例覆盖两种顺序，并已验证「去掉修复后会失败」。
- **设置页 / 讲座页的系统返回键无效**（此前只有页面内按钮能返回）。
  现在系统返回（含全面屏手势、三键导航、Android 13+ 预测式返回）与按钮行为一致。
- 讲座排序改为**「从最近到最远」**：近期讲座按最先开讲在前，已结束归档按刚讲完在前
  （此前最旧的排在最前，最近那场沉在几百条列表底部）。起止时间缺失的条目统一排在最后。

#### 已下线（诚实记录）

- **第三方公开讲座 feed**：曾用作展示源，但它已停止更新（快照整体滞后数月），已下线。
- **从个人课表猜讲座 / 课表回填一键签到**：先是从课表里按关键词筛讲座（会把普通课程误判成讲座），
  后改为「登录后扫描近 14 天课表，把 7 位 / 32 位标识写回对应讲座并一键签到」。
  两条路都已移除 —— 始终**没有证据**表明讲座会带 7 位节次码出现在 iClass 课表里。

#### 仍未做到（如实写明）

- **讲座一键签到不可用。** 预约系统给的是它自己的讲座编号，与 iClass 的
  7 位 `courseSchedId` / 32 位 `timeTableId` 是两套（本项目与上游 UCAS-Desktop
  各自独立得出同一结论）。会场编号（4 位）与注册表编号（5 位）同样不能当签到码用。
  签到请走「手动打卡」，直接吃现场读到的编号。
- **预约系统数据无法后台自动刷新**（见上）。
- 哨兵与通知都只能回答「有新的讲座」，**日期与场地仍以预约系统为准**。

#### 开发者须知

- 所有校内端点（主机、端口、后台路径、路径模板）都由 `android-app/local.properties`
  在构建时注入 `BuildConfig`，源码与文档里不出现。
  **从源码构建需先按 `android-app/local.properties.example` 创建该文件**，否则 Gradle 直接报错；
  仅安装 APK 的用户不受影响。
- 发布命令：`./gradlew :app:testDebugUnitTest :app:assembleRelease` ——
  单测与出包放在同一次调用里，单测不过就不出包。
- 明文放行只针对注册表那一个域名，另留一个**可选**逃生口
  （`ucas.net.extraCleartextHosts`）：若某个环境的登录跳转经 `http`，改本地配置即可，不必改代码发版。

### 1.1.13

- **修复：设置页系统返回键无效**。此前在设置页按系统返回键 / 手势返回会直接退出 App，
  只能点页面左上角的「返回」。现在系统返回（含全面屏手势、三键导航、Android 13+ 预测式返回）
  与页面按钮行为一致，都回到首页。
- **设置页状态可在旋屏 / 进程重建后保留**（`rememberSaveable`），不会突然跳回首页。
- 行为细节：设置页里的弹窗（小部件图文指引、锁定后台步骤、开源许可）仍由系统返回键优先关闭弹窗，
  不会连带退出设置页；退出登录后系统返回恢复为默认的「退出 App」语义。

### 1.1.12

- **后台自动签到**：每节课在「开课前 15 分钟 ~ 上课时刻」之间随机取一个时刻签到。
  随机值**只存在于内存、绝不写入本机**，且**每节课重新随机**，不在设备上留下可识别的固定模式。
- **通知栏常驻提示**：常驻通知显示「自动签到运行中 · 下次自动签到 HH:mm · 课程名」；
  自动签到的**结果通知强制发出**，不受「签到通知」开关影响。
- **保活引导**：设置页新增「后台运行与省电」卡片，可一键弹出「忽略电池优化」授权框、
  跳转厂商自启动页、按 ROM 给出「锁定后台」分步说明，并实时显示各项状态。
- **低耗电模式**（可选）：关闭常驻通知与后台服务，只保留每节课一个闹钟。
- **耗电净下降**：守护进程存活时，小部件的数据兜底闹钟由 10 分钟放宽到 45 分钟
  （单这一项即减少约 100+ 次/天的唤醒）；自动签到改为事件驱动、零轮询。
